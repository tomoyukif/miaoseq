#### R1. `fraction_sample` の命名と実義のずれ

- **平易な説明**: 列名は「サンプルに占める割合」に聞こえるが、実際は「その gene に割り当てられたリードのうち何割がそのクラスタか」に近い（正確には primer trim 後の sample×gene 入力に対する比）。
- **なぜ問題か**: プレート全体の優占アレルを議論するときに、見かけ上大きな `fraction_sample` をサンプル占有率だと誤解する。
- **Issue（技術詳細）**: `fraction_sample = n_reads / n_in`（`n_in` = その gene バケツの入力本数）。計画 §6.3 で定義済み・列名維持方針。
- **Evidence**: `.clusters_from_ids`；README「Assemble column note」。
- **望ましい状態**: 現行どおり列名維持なら、レポート・論文で必ず定義を併記。
- **Impact**: 生物学的結論の誤読（占有率の過大／過小評価）。
- **Recommendation**: 出力レポートや README に短い定義を残す（現状あり）。必要なら別名列を追加検討。

#### R2. デフォルト設定ではリードの大部分が「未割当」になりうる

- **平易な説明**: vsearch は多数の小さなクラスタを作りうるが、実装はサイズ上位 `max_clusters`（既定 20）だけを残し、さらに `min_cluster_reads`（既定 5）未満を捨てる。結果、入力リードの多くがコンセンサスに寄与しない（以前の比較では割り当て率おおよそ十数％台）。
- **なぜ問題か**: 「サンプルの全多様性をクラスタ数で見た」つもりが、実際は「大きいものだけ見た」になる。希少 OTU／低頻度アレルを議論するには不向き。
- **Issue（技術詳細）**: 上位以外は `max_clusters_overflow`、少数は `below_min_cluster_reads` として `unassigned_to_cluster.tsv` に出る。
- **Evidence**: linclust 比較時の vsearch 割り当て率 ~13.9%（32 samples）；コードの top-`max_clusters` 切り捨て。
- **望ましい状態**: 用途が「主要代表の復元」であることを明示。多様性定量が目的ならパラメータ変更や別指標が必要。
- **Impact**: 16S 等の多様領域で、希少種の欠落と誤解されやすい。

#### R4. abpoa コンセンサスはクラスタ内の生物学的ヘテロを均しうる

- **平易な説明**: 1 つのクラスタから 1 本の代表配列を作るため、クラスタ内に本当に違う変異が混ざっていても、多数派寄りの一本にまとまることがある。
- **なぜ問題か**: Assemble のコンセンサスを「サンプル内の全アレル一覧」と読むと、低頻度の真変異を見落とす。これは旧 spoa でも同型の限界で、abpoa 固有の新規欠陥ではない。
- **Issue（技術詳細）**: 計画どおり Assemble と Editcall は分離。厳密な編集頻度は経路 B。
- **Evidence**: §15 / §0.1（経路分離）；`cluster_purity` で均一性の手がかりは出る。
- **望ましい状態**: Assemble = 代表復元、Editcall = 変異頻度、と使い分ける。
- **Impact**: 経路の誤用時の偽陰性／単純化。
- **Recommendation**: 運用文書で経路の役割分担を再掲。多様領域では `min_cluster_purity` や閾値を検討。
- **ユーザー方針**: （ここに記入）
